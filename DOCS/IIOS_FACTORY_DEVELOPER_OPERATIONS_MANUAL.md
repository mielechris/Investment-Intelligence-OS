# IIOS Factory Developer & Operations Manual

## Truth and authority

The factory distinguishes container integrity/freshness from underlying evidence freshness. `CURRENT`, `STALE`, `INCOMPLETE`, `UNAVAILABLE`, `FAILED_CLOSED`, `NOT_ACTIVATED`, `RESEARCH_ONLY_UNPRICEABLE`, `CLOSED_HOLIDAY`, and `OPEN_24_7` are not interchangeable. Null is never zero. Registry membership is not availability.

The browser is a single read-only consumer. It cannot publish, invoke scanners, access Keychain, contact providers, read private evidence, write ledgers, create orders, or grant execution. Provider, credential, automatic-promotion, paper-order, broker, ledger-write and live-execution authority default false.

## Development workflow

Work from an exact clean feature checkpoint. Establish an explicit allowlist; use synthetic fixtures; run focused and complete tests, compilation, schema validation, lint, both builds, leakage/authority scans and diff checks. Leave changes unstaged until human review. Generated builds, state, logs, databases, secrets and private evidence are never committed.

## Tuesday operations

Use the checklist, product/source matrix, method/product matrix, professional-research matrix, sleeve specification and post-close template in `SUPERBATCH_20_TUESDAY_OPENING_DAY_FACTORY.md`. A $10,000 sleeve is a normalized comparison basis, never deployable or additive capital. Only authentic point-in-time outcomes can support a method score.

## Preview and activation

Fixture review uses an unused loopback port and an owner-only temporary root. Persistent rebuild/restart, source activation, credential use and provider traffic are separate approval gates with byte-for-byte rollback evidence. Never modify protected services as part of source implementation.

## Recovery

Fail closed on unsafe files, schema/hash mismatch, future timestamps, private fields, changed paper truth or enabled authority. Preserve the last authentic artifact. Roll back only the explicitly changed component and prove protected PID/start-time, paper, authority and repository equality afterward.

## Truth and provenance

Supported states are `CURRENT`, `AVAILABLE`, `AVAILABLE_EMPTY`, `STALE`, `INCOMPLETE`, `UNAVAILABLE`, `FAILED_CLOSED`, `NOT_ACTIVATED`, `RESEARCH_ONLY_UNPRICEABLE`, and `INSUFFICIENT_SAMPLE`. Publication freshness never upgrades underlying evidence freshness. Missing values remain null or unavailable and never become zero. Browser data is limited to sanitized projections and read models; private paths, source text, transcripts, credentials, raw errors, provider bodies, and private 9I evidence are prohibited.

Ambient Gallery motion depicts readiness, waiting, inspection, debate, filing, or cleanup only. Evidence movement requires current immutable candidate lineage. Ambient presentation never implies a candidate, trade, position, order, recommendation, endorsement, profit, provider connection, or current market evidence.

## Capital and research

The operational paper fund is a separate governed $10,000 fund. The 24 synthetic sleeves each use a normalized $10,000 comparison basis and are not funded, pooled, or deployable. They cannot alter operational NAV, cash, positions, transactions, orders, fills, or ledger. Professional observations are attributed hypotheses and cannot independently create or promote candidates.

## Daily owner workflow

1. Verify repository checkpoint and clean index/worktree.
2. Record protected service PIDs/start times and health.
3. Verify projection integrity, sequence, publication freshness, and underlying evidence freshness separately.
4. Verify paper NAV/cash/activity and every authority lock.
5. Identify approved market phase and run only its documented read-only checklist.
6. Review blockers and evidence gaps; never activate a source from the browser.
7. At post-close, reconcile products, methods, candidates, decisions, costs, outcomes, sleeves, provider accounting, paper changes, and authority.

Monday proves `CLOSED_HOLIDAY`; Tuesday exercises pre-market, regular session, mixed/stale/unpriceable/incomplete evidence, candidate-lineage failure, provider and professional failure, Committee/Risk rejection, sleeve observation, close, post-market, post-close, and complete fail-closed behavior. Fixtures are always labeled non-live and cannot support profitability claims.

## Rollback and troubleshooting

Before any persistent bundle or configuration change, retain byte-for-byte owner-only backups plus sanitized hashes and metadata. Stop only the exact job; require label, PID, port, and lock teardown barriers; bootstrap once; roll back automatically on the first mandatory failure. Never retry by weakening a gate. Diagnose unavailable sources from sanitized fixed categories. Never inspect private evidence or retimestamp stale data.

## Developer extension process

Extend the existing module registry, shared snapshot provider, product/method contracts, and canonical Museum shell. Add fixed schemas, bounds, provenance, freshness, null handling, human gates, authority-false assertions, deterministic fixtures, responsive/accessibility tests, and rollback documentation. Do not add competing roots, polling owners, schedulers, source-path selectors, simulated live data, or implicit provider authority.

Source activation proceeds in separately approved licensing waves. Ranking requires sufficient authentic point-in-time outcomes, transaction costs, slippage, walk-forward and out-of-sample validation, drawdown and calibration. Correlation alone establishes neither causality nor profitability.
