# Alpha Radar synthetic native adapter

This is a test-only execution path. Every accepted confinement-adapter input and retained
receipt is SYNTHETIC_TEST_ONLY. The separate lifecycle-only mode below has its own non-promotable receipt scope. Synthetic success cannot qualify a provider,
account, live runtime, Factory/Northstar integration or production installation.
Both production guards CLI_LIVE_ONLY and RADAR_NATIVE_ADAPTER_PENDING remain.

The production wrappers and synthetic adapter share alpha_session_execution
(scheduling, durable day reservations, independent completion-parent checks and
bounded receipt files) and provider_gateway_https (one bounded TLS exchange).
Production route/account admission stays outside these shared mechanisms.
No production entrypoint imports the native test adapter.

## Inputs and independent pins

Use a newly reviewed source inventory and fresh runtime; the base commit does not
identify edited code. A descriptor must bind the package, runtime, plan, ordered
universe, schedule, fixture and rendered confinement hashes independently. It
also pins the three native observation/launch tools, clock mode and total timeout.
The separate native authorization must pin the descriptor bytes themselves.
Only one new, exact owner-only source-test root is admitted. Runtime files are
single-link, owner-owned, read-only or executable/read-only, with exact membership,
bytes, modes and inode identities. Extra runtime files are rejected. Credential
modules and real selector fields are rejected, including in OFFLINE_TEST inputs.
No retained synthetic package is relabeled or reused as newly accepted evidence.

The fixture endpoint is exactly 127.0.0.1 and one independently pinned port. Its
CA/server certificate and disposable TLS private key belong only to the synthetic
runtime. No provider credential is needed. No DNS, redirect, proxy, pagination,
retry, alternate address or provider fallback is implemented. The fixture server
avoids HTTPServer's default reverse lookup. Payloads are ephemeral; receipts retain
only validated coverage/timestamp classifications, fixed local errors and hashes
of sanitized receipts. Synthetic quote prices never enter receipts.

## Native execution gate — not executed by offline tests

The parent verifies the interpreter/import closure and exact rendered confinement
profile, then launches only the pinned fixture and worker under sandbox-exec.
The deny-default profile admits runtime/output reads, limited system runtime
reads, output writes and one loopback endpoint. It grants no Keychain service,
credential-store read, public network or arbitrary executable access. Child OS
policy queries require denial of a disposable outside-root input and unrestricted
networking before any fixture or exchange starts. A rejection is retained and
never bypassed. These profile rules require actual macOS native qualification;
offline mocks do not prove their host compatibility or kernel enforcement.

PID, PPID, start time, exact argv, cwd, executable bytes, package/runtime pins and
startup parent hashes are reconciled before readiness and before each signal.
A pinned sandbox launcher may transition once to the pinned interpreter, with
stable PID/PPID/start/cwd and three final observations. Unknown partial starts are
retained and never signaled. Cleanup continues after individual errors; forced
stop requires another identity verification. Listener ownership must match the
fixture PID and exact endpoint. Three final port-clear observations are mandatory.
No process group, unrelated PID or unverified child receives a signal.

The complete schedule is one ten-symbol preflight plus 79 scans of six batches
(100/100/100/100/100/17): 475 maximum requests, no extra enrichment calls. Three
starts per rolling logical minute, 20-second wire/response deadlines, 1,000,000-byte
responses and missed-window rejection remain mandatory. The logical clock and
actual UTC wire times are distinct. ACCELERATED_LOGICAL_TIME is not proof of real
elapsed pacing; require an additional bounded wall-clock pacing and timeout run.
REAL_SESSION_TIME needs roughly the 06:20–13:15 PDT interval and cannot backfill.

## Validation and authority

Offline tests mock sockets, TLS, process creation, inspection and signals. They
must run only in a fresh artifact root with an outer no-network/no-process audit
boundary. Native scenarios remain NOT RUN until separately authorized with exact
source/runtime/package/profile/TLS/descriptor/port/root pins. Include the full
475-request journal, deadline/size/schema/coverage/freshness failures, duplicate
start, partial launch, interruption, independent recovery parents, PID reuse,
cleanup continuation, surviving listener and port clearance. Preserve failed runs.

All four authorities are false: broker_connected, paper_order_permission,
trade_execution_permission and live_execution. There is no installation or arming
path. A final synthetic audit records session evidence, startup parents and cleanup;
it cannot manufacture agents, Committee, Risk or production acceptance receipts.

Children wait at most ten seconds for the parent's hash-bound startup
acknowledgment, and also enforce their own bounded overall deadline. Unknown
partial starts can therefore self-exit without an unverified parent signal.
Failure evidence uses the original admitted output identity even when runtime
verification fails; that persistence path cannot grant a dispatch capability.
Synthetic journal verification caches only immutable canonical document bytes.
Every disk read still checks the actual file identity and expected hash; changed
bytes cannot reuse a cached verification result.


## CI_NATIVE_LIFECYCLE_ONLY — separate, manual, non-production

The three-attempt sandboxed fixture series is CLOSED RED. OS confinement remains
UNQUALIFIED. Push runs perform preparation and offline tests only; the exhausted
Seatbelt compiler matrix is no longer run on push. Existing confinement code and
policy remain intact and are not invoked by this separate lifecycle path.

The manual `lifecycle_only` input defaults false. It requires workflow_dispatch,
explicit true, native_startup false, an independently supplied exact source SHA,
a fresh GitHub-hosted macOS ARM64 runner and run_attempt 1. Missing, conflicting,
malformed or moving source inputs fail closed. There is no automatic retry.

Fresh immutable synthetic inputs remain under their original synthetic input
scope. Lifecycle output receipts are created as CI_NATIVE_LIFECYCLE_ONLY with
production_qualified=false, os_confinement=UNQUALIFIED, provider_access=false,
credential_access=false, worker_launches=0, requests_attempted=0 and all four
trading authorities false. They use a separate schema and descriptor parent.
Legacy synthetic, live and production admission cannot consume these receipts.
Rehashing or relabeling old evidence never creates independent acceptance.

Only the pinned fixture is started, without sandbox-exec. The parent passes a
positive nonsensitive environment; no repository token, provider selector, proxy
or credential field is forwarded. The fixture requires this exact environment.
An application audit guard rejects DNS, non-pinned addresses, external sockets,
child subprocesses, signals and unauthorized writes. This is application defense
in depth, not an OS sandbox or a claim of hostile-code isolation. The supervisor
admits only its exact one fixture launch and bounded ps/lsof observations.

PID, PPID, start time, exact argv/cwd, executable bytes, immutable runtime/fixture
and independently computed startup/acknowledgment parents must agree. A pinned
numeric-loopback TLS handshake sends no HTTP request. No worker, market schedule,
provider transport, broker, ledger, installation or arming path is invoked.

Shutdown is cooperative through an exclusive hash-bound stop receipt. There is
no signal fallback in this mode: if cooperative shutdown fails, cleanup stays
failed. Verified zero exit, child-exit receipt, prior listener ownership and three
stable port-clear observations are required together. Early child exit or missing
ownership never becomes successful cleanup merely because a port is clear.
Primary failure and cleanup failure are retained separately with bounded sanitized
child hints. A passing lifecycle is not SYNTHETIC_NATIVE_QUALIFIED, confinement
qualification, Monday readiness, or production acceptance.

A later full 475-request synthetic loopback session requires a new explicit
review and authorization. Lifecycle-only selection cannot launch its worker.
