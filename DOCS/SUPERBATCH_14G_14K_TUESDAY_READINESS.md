# Superbatch 14G–14K Tuesday readiness

## Immutable candidate lineage

The browser candidate batch is derived only when the replaceable 9E state identifies an exact immutable successful cycle and both completion timestamps match. The canonical cycle payload is hashed, candidate and batch identifiers are deterministic, and no more than five allowlisted rows leave the publisher. Raw evidence, prompts, labels, scores, model output, paths, private fields, and credentials are excluded.

A failed, missing, stale, or mismatched cycle is `UNAVAILABLE`: its aggregate candidate count is removed and no batch is published. A successful cycle containing no candidates is `AVAILABLE_EMPTY`. Audit replay of successful old cycles is permanently labeled `HISTORICAL_REPLAY_ONLY` and cannot replace current evidence.

## Credit and empty-batch boundary

The Financial Datasets checkpoint has a once-only, explicitly authorized initializer for the reviewed 3 confirmed / 2 ambiguous / 1,000 ceiling baseline. It requires the exact source-controlled attestation hash and a valid reviewed timestamp, preserves the hash chain and owner-only atomic store, and refuses replacement. It accesses neither Keychain nor a provider.

Zero-candidate batches are successful empty observations. Their replay checkpoint is written, with zero provider requests, zero credits, and zero cases.
