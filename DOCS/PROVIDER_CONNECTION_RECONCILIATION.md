# Provider connection qualification boundary

This source adds a separate opt-in qualification path. Offline results never establish provider readiness. The existing OFFLINE_ONLY gateway, its roles, its assertions and the Yahoo/Northstar/Hercules architecture remain unchanged. No service, CLI startup, installation, account creation or credential provisioning is provided.

The supported qualification requests are Alpaca multi-symbol market snapshots; Massive comma-filtered stock snapshots; Financial Datasets MU company facts; Bigdata fast MU company-research retrieval with at most ten chunks; and Alpha Vantage MU daily SMA(20, close). Other corporate endpoints and enrichment functions remain outside this first transport scope. This does not remove existing logical gateway coverage.

## Admission and evidence

`admit(manifest, account, runtime, expected=..., now=...)` requires independent SHA-256 pins for all three public documents. Each account proof must bind an authoritative sanitized evidence hash. The owner/reviewer must inspect that evidence before accepting its hash; a checksum does not authenticate a provider or prove a claim. Synthetic test proofs belong only to OFFLINE_TEST. The null template cannot dispatch.

The manifest binds the exact provider, accepted role, method/host/path/logical endpoint, parameters, sorted symbol set, explicit feed, one-request limit, currency/unit and cost ceiling, time window, immutable runtime/source parent and exact output root. All existing operational/trading/ledger authority flags remain false. A separate expiring `qualification_authorized` field permits only the pinned qualification request after later owner authorization. There is no provider, account, selector, endpoint or feed fallback. SIP must be independently entitled; paper credentials do not prove it.

Account evidence must identify the provider/account/tier, exact selectors, endpoint/symbol/feed scope, applicable internal-use and storage rights, current unreserved allowance, rate slot, cost unit and maximum charge. Overage and automatic top-up must be false. Failed/ambiguous billing must allow reserving the maximum without retry. Each of endpoint, symbols, feed, rate, cost, internal_use, billing, selector_binding and retention requires a VERIFIED proof with an evidence hash. Validity must cover the authority window.

Retention permission must expressly cover raw bodies, normalized observations, references and hashes and identify the controlling agreement and retention horizon. Bigdata additionally requires explicit API storage permission and no grounding/model call. References are not exempt. Unknown or incompatible retention prevents dispatch and response storage; obtain an applicable written agreement rather than changing evidence requirements. The code does not perform expiry deletion: later retention-compliant disposal needs separate authority before the approved retention horizon.

## Runtime and transport

A separately reviewed runtime manifest binds an exact immutable root, all files with sizes/modes/hashes, interpreter, TLS bundle, imported source files, source commit and one numeric IPv4 address per enabled provider. Every runtime file is owner-owned, singly linked and mode 0400/0500; directories reject writes. Exact inventory, path containment and symlink checks reject substitution. Live invocation verifies the actual interpreter, prefix and all loaded module files against that closure. The accepted OFFLINE_ONLY source commit cannot identify the new implementation. A later source checkpoint must be independently pinned. Platform shared libraries and native OS trust remain an additional runtime qualification prerequisite; this source-only batch does not package or qualify them.

`qualify` requires explicit credential and network objects. LIVE_QUALIFICATION accepts only the native boundary types and wall clock; OFFLINE_TEST rejects them. Tests mock Security.framework, TLS and socket boundaries. No executable imports start requests or retrieve secrets. Native transport uses a separately pinned numeric address, one socket, hostname-checked TLS >=1.2 and one fixed route. No DNS lookup/fallback, proxy environment, redirects, compression, pagination or retries. Time remaining is reapplied to connect, TLS, headers and body chunks. A qualified address pin must be refreshed through separately authorized DNS/runtime preparation; failure never chooses another address.

Credentials use the exact selectors listed below and account `iios-provider`. The wrapper lazily invokes Security.framework, never password-output CLI flags. Secret representations are redacted. Raw/URL/base64/JSON-unicode echoes and sensitive field names are rejected before body hashing/publication. Credential buffers are cleared at scope exit; Python/SSL immutable string copies cannot provide a physical-memory zeroization guarantee. Do not enable request tracing, debugger local-variable capture or crash dumps in a future qualified runtime. No credential is printed, persisted or included in a receipt hash.

## Durable bounded qualification

The output root is independently pinned, canonical and owner-only. A descriptor-relative exclusive-create reservation is fsynced before any credential or network operation; advisory locking prevents concurrent dispatch. One provider slot exists per bound batch root. A crash leaving a reservation incomplete blocks the batch, as does an ambiguous response. A new provider request must not obtain a fresh root to evade its approved batch budget. No cleanup deletes evidence or signals processes.

Recovery requires two explicit caller inputs: `recovery` and `expected_recovery`. The latter is an independently trusted SHA-256 of the canonical recovery document, supplied by the owner/reviewer; it must never be inferred from the records being recovered. No helper auto-trusts on-disk hashes. Missing recovery evidence blocks any existing batch, including one whose prior provider artifacts are all absent; absence must not reset its budget. Only a newly created batch with no prior records can start without recovery pins. The recovery schema is `iios-provider-recovery-v1`, with exactly `batch`, `next_request` and `entries`. `batch` binds batch_id, root, scope, source_commit and runtime_parent. `next_request` equals the independently accepted manifest hash for this invocation. Entries must exactly match every prior provider's reservation/receipt/response file set; missing or orphaned artifacts block recovery.

Each entry supplies `request_id` (the complete prior manifest hash), `parents` (manifest/account/runtime), and independently trusted exact-byte SHA-256 values for reservation, receipt and response. Verification checks file ownership/modes, no symlink/hardlink aliases, bounded JSON and duplicate-key rejection, exact bytes, receipt self-hash, normalized observation hash, raw response hash, all reservation/response parents, provider/role, batch/root/scope/source, request identity, cost and recovery parent. Only after all checks pass may OBSERVED permit the next provider. A self-consistent receipt hash or OBSERVED label alone is never sufficient.

New reservation and receipt records explicitly bind batch_id, root, scope, source_commit, provider, role and request_id. A valid recovery of the identical completed request returns the original receipt without credential access, dispatch or record replacement. The same provider slot cannot be reused for a different request. A fresh externally reviewed recovery document is required after another provider completes; replaying an old document fails exact membership/next-request checks. STOP or ambiguous/incomplete records remain blocking. Invalid recovery never removes, refunds, recreates or releases reservations. Older records lacking these identities remain preserved and cannot be relabeled or upgraded into recoverable evidence.

Failures publish fresh sanitized evidence where the output root remains writable. Existing records are never overwritten. Response bytes are hashed only after sensitive-value and schema checks; raw byte identity remains distinct from normalized JSON identity. Provider event/publication times, absent coverage, duplicates, errors, delay contradictions and provider-reported usage remain separate. Missing timestamps remain unknown, unchanged prices are not independently stale, and Bigdata query association does not prove ticker coverage. Billing remains UNVERIFIED even for HTTP 200 unless separately reconciled against authoritative account usage. Every receipt's provider readiness remains NOT_READY. Expired, malformed or policy-blocked inputs fail before provider access; the caller retains its sanitized failure diagnostics.
